# GPT-4o provider smoke test — 2026-08-14

## Configuration

- Variant: `openai`
- Flue model: `openai/gpt-4o`
- Credential binding: `OPENAI_API_KEY`, scoped to the agent Worker
- Prompt: `Reply with exactly PONG and nothing else.`

## Result

The standalone Flue runner loaded the agent, selected GPT-4o, reached the
OpenAI API, and returned exactly `PONG`. A final clean validation completed in
7.7 seconds wall-clock, including Varlock decryption, runner startup, the model
request, and process teardown; it is a smoke-test duration, not model-only
latency.

The smoke test also exposed and fixed a Node-only loading issue: the notes tool
now loads its Cloudflare context lazily, so `flue run` can start outside a
Worker runtime when the selected prompt does not invoke a notes tool.

## Re-run

With `OPENAI_API_KEY` resolving through Varlock:

```sh
nubx varlock run -- \
  nub --no-env-file node_modules/@flue/cli/bin/flue.mjs run \
  src/workers/agent/agents/hello.agent.ts \
  --name Hello \
  --message "Reply with exactly PONG and nothing else." \
  --data '{"userId":"gpt4o-experiment","modelVariant":"openai"}' \
  --env /dev/null \
  --json
```

For the A/B latency run against the full local stack:

```sh
AB_VARIANTS=openai,workers-ai \
AB_ROUNDS=3 \
AB_EXPECT=PONG \
nub run benchmark:agent-models
```
